## Rule
An agent may stage, commit, and create or delete **local** branches. An agent
must never run `git push` (with or without `--force`, `-u`, or a refspec), and
must not reach a remote by any other route: no `gh pr create`, `gh release
create`, `gh repo edit`, or API call that writes to the remote. Read-only
remote commands (`git fetch`, `git log origin/...`, `gh repo view`) are fine.

Work is handed over by leaving the commit or branch local and saying plainly
what is ready to push and the exact command. The human runs it.

## Rationale
Pushing is the moment work becomes public and hard to retract — it can expose
content, trigger CI, notify watchers, and be mirrored or indexed even if the
branch is deleted afterward. That call belongs to the repository owner, not to
an agent, and it stays true for branches created *because* they are meant to be
published: `release` (DEC-0009) is a distribution branch and is still pushed by
hand. Stated by the user on 2026-08-14 after an agent paused on exactly this
question; the pause was correct, the rule makes it permanent.

## Exceptions
none. An explicit, in-the-moment instruction to push is an instruction to print
the command for the human to run.
