---
id: RUL-0006
type: rule
title: Hand off one gated step at a time; never a block that spans a human action
date: 2026-08-14
tags: [workflow, git, safety, anti-drift]
summary: Commands given to the human stop at the first step whose success the agent cannot verify — later steps are withheld until that one is confirmed, not printed under an "after X" heading.
applies_to: every command handed to the human under RUL-0004; every multi-step DEC-0010 flow
---

## Rule
When handing over commands under RUL-0004, print only the commands that can be
run **now**. Stop at the first step that depends on an outcome the agent has not
yet verified — a merge, a review, a push landing.

- A prose heading (`## After merge`, "once this passes") is **not** a gate. A
  reader with a terminal open runs a contiguous block of commands. If a step
  must not run yet, do not print it yet.
- After the human reports back, verify the gating step actually completed
  (RUL-0005), then hand over the next block.
- When a command's success is not obvious from its own output, say what the
  human should see, so a silent no-op is distinguishable from success.

## Rationale
On 2026-08-14, PR #2 was handed over as `gh pr ready 2` followed immediately by
a `## After merge` block containing `git checkout main && git pull`,
`tools/build-release.sh`, and `git push origin release`. The block was run before
the merge landed. `build-release.sh` read an unchanged `main`, reported "release
is already identical to main — nothing to do", and the checkout silently reverted
the working tree to the pre-fix docs — output that looks like a broken tool or
lost work, when the process had simply been run out of order.

The agent cannot run these commands and cannot see them run, so sequencing is the
only control it has. Withholding a step costs one message; a prematurely run step
costs a debugging detour and erodes trust in the tooling. This rule is the
handoff-side complement to RUL-0005: RUL-0005 governs what the agent may claim,
RUL-0006 governs what it may hand over.

## Exceptions
Consecutive commands whose outcomes the agent does not need to verify between
them — creating two labels, or `git add` then `git commit` — may be printed as
one block. The gate is the need for verification, not the number of commands.
